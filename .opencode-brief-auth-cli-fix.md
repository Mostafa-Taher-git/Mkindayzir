# OpenCode task — FIX the "Authentication required" dialog on http://localhost:5000

## The problem (user-facing)
When the user opens http://localhost:5000 in their browser (Brave/Chrome on Pop!_OS),
a native "Authentication required" Basic-Auth dialog appears and blocks the app.
The user has cleared the browser HTTP auth cache and it persists. They want it FIXED
via CLI, not by manually clicking browser GUI.

## ALREADY PROVEN (server is innocent — do not re-litigate with curl alone)
- `curl -D - http://localhost:5000/` -> `HTTP/1.1 200 OK`, **no `WWW-Authenticate` header**.
- `ss -tlnp | grep :5000` -> only `python` (the OpsDesk `python run.py`) listening.
- No proxy env vars, no proxy port listeners, gsettings proxy = `none`, no proxy flags
  in the brave process.
Conclusion: the OpsDesk server never sends a Basic-Auth challenge. The dialog is created
client-side — a cached HTTP Basic-Auth entry and/or a browser extension in the user's
NORMAL browser profile.

## YOUR JOB — do the CLI fix, prove it works
1. **Launch a clean, isolated browser profile** (no extensions, no cached auth, no proxy)
   from the CLI. This is the actual fix — it bypasses the corrupted normal profile:
   ```bash
   /opt/brave.com/brave/brave --user-data-dir=/tmp/brave-clean --disable-extensions \
     --no-proxy-server --no-first-run http://localhost:5000
   ```
   NOTE: this opens a GUI window (requires a display). If no display is available, instead
   verify the hypothesis another way (see step 2) and report the limitation.
2. **Confirm the server is still serving 200 with no challenge** (sanity, since the user
   may have stopped it):
   ```bash
   curl -s -D - -o /dev/null http://localhost:5000/ | grep -iE "HTTP/|www-authenticate"
   ```
   If it returns nothing / connection refused, tell the user to start the server first:
   `cd "/media/dell/New Volume/Projects/OpsDesk" && . venv/bin/activate && python run.py`
   (leave it running).
3. **Rule out extensions vs wrong URL**: If the clean-profile launch works (no dialog),
   the cause is confirmed as cached-credential/extension in the normal profile. Report the
   exact fix: either keep using the clean profile, OR clear the normal profile's auth cache
   at `brave://net-internals/#auth_cache` -> Clear.
   If the dialog STILL appears even in the clean profile, capture the EXACT address-bar URL
   (it is then a tunnel/forwarded port, not localhost:5000) and report it.
