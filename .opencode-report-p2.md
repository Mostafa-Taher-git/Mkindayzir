===========================================================================
VERDICT: needs-rework
===========================================================================
The API layer is mostly sound (RBAC on read/author, CSRF, draft hiding,
empty-title/body 400s all confirmed against the live server), but the SPA
navigation for the entire feature is broken: the router can never dispatch
to the article, Manage, or New/Edit views, and the shell sidebar has no KB
link at all, so the Help Center is unreachable from the UI. On top of that,
three uncaught-exception paths return HTML Werkzeug debugger pages (500)
that dump stack traces and source, and feedback/delete/publish have
authorization or dedup gaps. This needs work before shipping.

===========================================================================
BUGS
===========================================================================
1. (HIGH) SPA can never render an article, Manage, or New/Edit view.
   static/js/app.js:201-216 declares routes "/kb/manage", "/kb/new" and
   "/kb/:id", but the router at app.js:224-227 splits the hash on "/" and
   uses only the FIRST path segment as the key, so #/kb/2, #/kb/manage and
   #/kb/new all dispatch to "/kb" (viewKb). Clicking a KB card (navigate
   "/kb/<id>", app.js:89) just re-renders the list; Manage and the authoring
   form are dead routes.
   FIX: match the full path (e.g. strip the id, look up "/kb/manage" /
   "/kb/new" before falling back to "/kb"), or dispatch on a longer prefix.

2. (HIGH) No navigation entry point to the Knowledge Base at all.
   static/js/app.js:238-256 shell() builds the sidebar from navItems and
   never adds a link to /kb (Help Center) or /kb/manage. The only KB links
   are internal "Back to Help Center" / "New Article" actions inside the
   unreachable views, so a user can never reach the feature.
   FIX: add sidebar items (e.g. "/kb" for everyone, "/kb/manage" for
   agent/manager/admin).

3. (MEDIUM) POST /api/kb/<id>/feedback on a missing/deleted article throws
   an unhandled sqlite3.IntegrityError (FK constraint on kb_feedback.
   article_id) -> HTTP 500, and in debug mode returns the full Werkzeug
   interactive debugger HTML (stack trace + source). Verified live with
   POST /api/kb/999/feedback.
   FIX: look up the article first and return 404, before inserting.

4. (MEDIUM) POST /api/kb with a non-existent category_id -> unhandled
   IntegrityError -> HTTP 500 debugger page (verified live, category_id=999).
   FIX: validate the category exists and return 400.

5. (MEDIUM) GET /api/kb?category_id=abc -> unhandled ValueError from
   int(cat) at app/routes_kb.py:56 -> HTTP 500 debugger page (verified live).
   FIX: wrap in try/except and return 400.

6. (LOW) GET /api/kb/<id> returns a stale views value.
   app/routes_kb.py:78-84 increments views AFTER the SELECT but serializes
   the pre-increment row, so the response always lags the stored count by
   one (verified: response showed 0 while list endpoint showed 1; repeated
   GETs inflate the counter each time).
   FIX: re-fetch the row after the UPDATE before returning.

7. (LOW) No server-side title length cap. Frontend maxlength=100
   (app.js:157), but app/routes_kb.py:95-99 only validates body against
   config.MAX_KB_BODY; a 5000-char title was accepted (verified live).
   FIX: add a MAX_KB_TITLE check in create and edit.

8. (LOW) Article body renders as a single <p> (app.js:107) with no
   white-space:pre-wrap, so multi-line/paragraph body text is collapsed
   into one block — authors' formatting is lost on read.
   FIX: give .kb-body (css/app.css:250) white-space:pre-wrap or split on
   "\n\n" into paragraphs.

===========================================================================
SECURITY
===========================================================================
1. (MEDIUM) Werkzeug debugger / stack-trace disclosure on uncaught
   exceptions. Bugs 3-5 above all 500 with the interactive debugger HTML
   (eval console + full traceback/source) because _json_api_errors
   (app/__init__.py:87-100) only catches HTTPExceptions, not raw
   IntegrityError/ValueError. Even with debug off, the API returns HTML
   instead of JSON. FIX: pre-validate inputs (return 400/404) and/or add an
   app-level handler that returns JSON for /api/* on any 500.

2. (MEDIUM) AuthZ: any agent may publish or delete ANY article.
   app/routes_kb.py:138-154 (publish) and 157-166 (delete) check only the
   role, while edit (app/routes_kb.py:120-122) correctly scopes to author or
   manager/admin. Verified live: hragent@ (a different-team agent, not the
   author) published the IT agent's draft and deleted another agent's
   article. FIX: apply the same author-or-manager/admin check to publish and
   delete as to edit.

3. (LOW) Views counter is trivially inflatable. Any logged-in user (staff
   or requester) can spam GET /api/kb/<id>; the count also includes staff
   reads and the author's own reads, and there is no per-session/idempotency
   guard. FIX: count only requester reads, dedupe per session, or rate-limit.

4. (LOW) Feedback allows unlimited duplicate spam and is unattributable.
   kb_feedback (app/db.py:185-191) has no user_id and no unique constraint,
   so one user can insert unlimited votes/comments for the same article
   (verified: 5 consecutive 200s from one requester). The "Was this
   helpful?" buttons also stay enabled after voting. FIX: add user_id +
   UNIQUE(article_id, user_id) (or upsert), and disable the buttons once a
   vote is recorded.

5. (LOW) Body is stored and returned raw (verified: <script>alert(1)</script>
   survives round-trip). This is NOT currently exploitable in the SPA: the KB
   views render title/body/category via el() text nodes / createTextNode
   (app.js:107, 91), never innerHTML, so there is no stored-XSS path today.
   However the el() helper supports an "html" attribute (app.js:22) and the
   raw body is re-served to every role; the safety depends entirely on every
   future view avoiding that attribute for this field. RECOMMEND sanitizing
   on write or rendering with an explicit escaping-only component.

6. (INFO) CSRF is correctly applied to every mutating KB endpoint
   (app/routes_kb.py:89,113,140,159,171 via @helpers.csrf_protect) and was
   verified live: missing/wrong X-CSRF-Token -> 403; unauth GET -> 401.
   Session cookie flags (HttpOnly, SameSite=Lax) are correct.

===========================================================================
UX / A11Y
===========================================================================
- No way to reach the Help Center or Manage KB from the UI (see Bug 2);
  KB article cards navigate to a route that re-renders the list (Bug 1).
- KB list cards are divs with role="link" + tabindex (app.js:88) rather than
  real <a href="#/kb/...">; no visible focus indication is guaranteed and
  middle-click/open-in-new-tab doesn't work.
- "Was this helpful?" buttons (app.js:111-113) show no selected/disabled
  state after voting and allow repeat votes (ties into Bug/sec 4); no
  feedback-again affordance.
- Article view (viewKbArticle) sets no document title and moves no focus on
  route change; screen readers hear nothing when the article loads.
- The search field has aria-label (good) and a 300ms debounce (good), but
  there is no "results for <q>" announcement when results update.
- Manage KB row buttons include Delete with confirm() but Publish/Edit have
  none; on a wide row the three buttons can wrap awkwardly (no wrap class).
- Body text collapsed to one paragraph (Bug 8) degrades readability of
  multi-section articles.

===========================================================================
IMPROVEMENTS (optional)
===========================================================================
- Router: consider a generic nested-path lookup so any two-segment route
  (e.g. "/kb/new", "/kb/manage") resolves before the first-segment fallback.
- Add a small client-side router test (test_frontend.js exists) covering
  #/kb, #/kb/manage, #/kb/new and #/kb/<id> dispatch.
- Extend tests/test_security.py to cover: requester GET of draft by direct
  ID -> 404, feedback on missing article -> 404, invalid category_id ->
  400, cross-agent publish/delete -> 403, and views lag/idempotency.
- Consider rich text / markdown for body with a whitelist renderer instead
  of a raw-text <p>, since the current single-paragraph display loses all
  formatting.
- kb_feedback should store user_id + created_at semantics if you want
  per-user analytics; expose aggregate "helpful yes/no" counts in the
  article payload for the Manage view.
- _serialize() (app/routes_kb.py:25-28) is a no-op passthrough; fold it in
  or remove to avoid implying it sanitizes rows.
