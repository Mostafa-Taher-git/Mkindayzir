## 1. What is ALREADY DONE (do not redo — build on it)

A previous agent (Hermes) performed a high-effort bug/security pass. These fixes are applied and verified against the live server:

1. **Login CSRF deadlock fixed.** `/api/auth/csrf` had `@login_required` but the SPA fetches CSRF *before* authenticating, causing a 401 that prevented login. Removed the decorator. `/api/auth/login` now enforces `@csrf_protect`.
   - Files: `app/routes_auth.py`
2. **Attachment files were publicly downloadable** because `UPLOAD_DIR` lived inside `static/` (Flask's static handler served them unauthenticated). Moved to `data/uploads` (outside static). The existing attachment was migrated and its DB `storage_path` updated.
   - Files: `app/config.py`, `app/__init__.py` (data dir created), `data/uploads/...` (moved file)
3. **Team deletion orphaned tickets/users.** Added explicit `UPDATE ... SET team_id=NULL` before `DELETE`.
   - Files: `app/routes_admin.py`
4. **`blocked_reason` was wiped on every non-BLOCKED status change.** Now preserved (only overwritten when moving *to* BLOCKED).
   - Files: `app/routes_tickets.py`
5. **`reopen_count` never bumped for manager/admin reopens** (only requester path). Now increments on every reopen except double-counting the requester path.
   - Files: `app/routes_tickets.py`
6. **`login_required`/`role_required` redirected to a non-existent `/auth/login` route** (would loop on the SPA). Now returns clean JSON `401`/`403`.
   - Files: `app/helpers.py`
7. **Missing attachment file returned 500.** Now returns `410`.
   - Files: `app/routes_tickets.py`
8. **Login form had prefilled credentials** (felt like no auth). Removed prefill.
   - Files: `static/js/app.js`

## 2. Items already VERIFIED CLEAN (do not "fix" — they are correct)

- RBAC: requester/agent/manager/admin scoping on tickets and `meta` (staff list hidden from requesters) is correct.
- CSRF via custom `X-CSRF-Token` header is genuine XSRF protection; login is now covered.
- SQL uses parameterized queries everywhere — no injection.
- Frontend HTML-escapes output via `esc()` — no stored-XSS path.
- Input caps (subject/description/comment length, allowed file types, 10MB) enforced server-side.
- 72h auto-close and 72h reopen window work as designed.

Then address the following production-hardening gaps **only if they are low-risk and clearly correct** — this is a LOCAL DEV app, so do not over-engineer:

- **B. Session cookie flags:** `SESSION_COOKIE_SECURE` / `HTTPONLY` / `SAMESITE` — set `HttpOnly=True` and `SameSite='Lax'` now (safe for dev and prod). `SECURE` only if behind HTTPS.

- **D. Rate limiting on `/api/auth/login`** to slow brute force (optional — a simple in-memory attempt cap is fine; do not add external deps unless already present).
- **E. Any bug you find that the prior agent missed** — implement a minimal, correct fix and describe it.

Do NOT add new dependencies (no `pip install`) unless one is already in `requirements.txt`. Do NOT change the database schema in a way that breaks existing data. Do NOT implement a full production deployment (gunicorn/Postgres) — that is explicitly out of scope.
