# Full App Audit — OpsDesk UI/UX + Functional Completeness

Date: 2026-08-17
Tester: direct code + live app review
Server: http://127.0.0.1:5000

## HIGH findings

### H1 — Priority field exists but is not enforced or surfaced as a real workflow
- Create form: `viewCreate()` in `static/js/app.js:903-946` offers Normal/Urgent.
- Backend: `routes_tickets.py:107-117` validates enum, but there is **no priority-based behavior change** beyond SLA policy matching.
- Queue/detail: `static/js/app.js:630,695,744` shows priority, but there is no explicit filter UI for priority on the queue, no bulk priority action, and no visible priority-change activity log entry.
- Fix: Add a priority filter control to the queue; log `priority_change` activity; surface priority change in ticket detail with a clear control.

### H2 — Assign-to-person exists but the flow is unclear and incomplete
- Backend: `routes_tickets.py:168-218` supports `POST /api/tickets/<id>/assign` with `assignee_id` or `self`.
- Frontend: `static/js/app.js:856-876` shows:
  - Agent: Claim button only (`self: true`), no pick-anyone UI.
  - Manager/Admin: modal with user dropdown, but no search/filter, no team filter, no obvious “Assign to me” shortcut.
- There is no assignee filter in queue, no “Assigned to me” view, and no assignee change history in the activity stream beyond generic `assigned` text.
- Fix: Add “Assigned to me” tab/filter; add assignee dropdown in ticket detail for agents too; filter users by team in assign modal.

### H3 — AI usage has no onboarding/help text
- Settings: `static/js/app.js:962-980` shows key input + model dropdown, but no explanation of what the three AI buttons do.
- Ticket detail: `static/js/app.js:283-301` shows “AI assist (draft only)” with no tooltip/help copy about capabilities, limits, or failure behavior.
- Fix: Add concise help text in settings and in the AI panel itself; explain draft-only, that it does not send anything to the requester, and what each button returns.

### H4 — No confirmation/undo for destructive actions
- `API.deleteKb(a.id)` in `viewKbManage` uses `confirm()`.
- Ticket delete/reopen/status changes do not always show a confirmation modal; `doReopen` in `static/js/app.js:898-901` is immediate.
- Fix: Use a shared confirmation modal for reopen, delete, and status transitions that require notes.

### H5 — Notifications may not cover all relevant events
- `app/notifications.py` covers `assigned` and `resolved`. There is no explicit notification for `status_change` to `blocked`, no comment notification to requester, no CSAT prompt notification, and no AI-draft notification.
- Fix: Add notifications for status changes that affect the requester, and for new internal comments visible to requester.

## MEDIUM findings

### M1 — Ticket detail layout inconsistency
- `kvRow` uses inline styles instead of design-token classes (`static/js/app.js:803-806`). This bypasses the theme system and creates inconsistency if tokens change.
- Fix: Replace inline borders/padding with token classes or a `.kv` helper in CSS.

### M2 — Settings page has no test coverage
- New `routes_settings.py` + `static/js/app.js:949-982` are not covered by `tests/test_security.py`.
- Fix: Add tests for save/load/clear AI key and for model persistence.

### M3 — Priority not filterable in queue
- `routes_tickets.py:59` accepts `priority` query param, but `static/js/app.js:630-677` does not expose it in the filter bar.
- Fix: Add a priority dropdown filter next to status/team filters.

### M4 — AI fail state UX is weak
- `static/js/app.js:289-294` shows “AI unavailable: <error>” as raw text. There is no retry button, no fallback hint, no rate-limit guidance.
- Fix: Add retry button, show a clearer message for 429/401/403, and disable buttons while generating.

### M5 — No “Assigned to me” or “My tickets” view for agents
- Agents see Dashboard + Queue, but queue filters are not persisted and there is no quick “My tickets” shortcut.
- Fix: Add a `/my` route for agents too, or add an “Assigned to me” filter in queue.

## LOW findings

### L1 — Year-aware dates partially fixed
- `fmtDate` now shows year when different, but `ago()` and activity timestamps in `renderActivity` still use relative time only, which can be ambiguous for older tickets.
- Fix: Show absolute date tooltip on hover for timestamps older than 7 days.

### L2 — Inline styles in create form
- `static/js/app.js:908,921` uses `style="max-width:640px"` and `style="padding:20px"` instead of token classes.
- Fix: Replace with `.card` + `.mt-4` + max-width token.

### L3 — No empty state for notifications when mark-all-read is used
- `openNotifications` refreshes list after `markAllAndRefresh`, but if all were read, the list still shows them rather than the “all caught up” state.
- Fix: Refetch after mark-all and render empty state if `notifications.length === 0`.

### L4 — No help/onboarding for first-time users
- First login shows no welcome tip, no onboarding checklist, no “How to create your first request” hint.
- Fix: Add a lightweight onboarding banner on first login (dismissible).

## Quick wins
1. Add priority filter dropdown to queue.
2. Add AI help text in settings and ticket detail.
3. Replace inline styles in `kvRow` and create form with token classes.
4. Add confirmation modal for reopen/delete/blocked status.
5. Add “Assigned to me” filter to queue.

## Polish pass (deferred)
- Skeleton loaders for all list views.
- Keyboard shortcut hints in tooltips.
- Dark/light contrast audit on badges and SLA pills.
- Empty-state illustrations for queue/kb/reports.
- Localization/i18n hooks.

## Feature gap summary
- **Priority**: visible but not a real workflow control.
- **Assign-to-person**: functional but hidden behind a modal; no bulk or quick self-assign for agents.
- **AI onboarding**: missing; users won’t know what the three buttons do or what draft-only means.
