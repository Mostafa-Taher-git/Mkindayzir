## Bugs Fixed

### 1. SPA router could not reach `/kb/<id>`
**File:** `static/js/app.js`  
**Problem:** The router only did exact-string matching for nested KB routes. Hashes like `#/kb/123` matched `routes["/kb"]` (the list view) instead of `viewKbArticle`, because `routes["/kb/:id"]` never matches a concrete hash.  
**Fix:** Added a fallback in `router()`: if `path === "kb"` and there is no exact nested route match, any `/kb/<something>` dispatch now falls through to `viewKbArticle`.

### 2. `me()` ignored global `AI_ENABLED` disable flag
**File:** `app/routes_auth.py`  
**Problem:** `me()` returned `ai_enabled=True` whenever the user (or deployment) had any OpenRouter key, even if `OPERADESK_AI_ENABLED=0` was set. This contradicted the fail-closed design in `config.py`.  
**Fix:** `ai_enabled` is now computed as `config.AI_ENABLED and has_key`, so the global disable flag is respected.

### 3. KB article body lacked explicit escaping (defense-in-depth)
**File:** `static/js/app.js`  
**Problem:** Article body was rendered as a raw string child. Safe today because `el()` creates text nodes, but no explicit escaping was applied.  
**Fix:** Wrapped `article.body` with the existing `esc()` helper in `viewKbArticle()` so any future DOM-manipulation path stays safe.
